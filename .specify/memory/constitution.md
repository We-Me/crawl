# 公开知识采集项目开发原则

版本：0.1.0｜日期：2026-09-11｜状态：评审草案，尚未批准为实施基线

本文件规定本项目的规格维护与实施约束。业务事实来自四份保留输入；新增工程处理明确标注为设计建议。原则版本为 0.1.0，编制日期为 2026-09-11，批准人及批准日期尚未确定。它是可评审候选，不代表项目已完成业务决策。

## 一 需求先于实现

每项业务实现对应稳定需求编号、可观察验收结果和输入依据。先维护 spec.md，再同步 plan.md、数据契约、tasks.md 与追踪矩阵；不能以代码现状反向伪造原文要求。计划变化需记录受影响需求和测试。

## 二 保留依据和强度

S1/S2 不因版本数字互相覆盖；S3/S4 是审查依据，不自动替代原件。原文的必须、建议、可选、条件必填、按需，以及两原文的阶段差异都必须保留。设计补充需要自己的决策记录；无法确定的事项可留待决而不能假定已批准。

## 三 原件保真与可追溯

公开采集结果保留原始资源、抓取依据和完整正文结构。采集清洗不翻译、摘要或改写事实。新版本不覆盖历史；失败不被静默丢弃。采集输出要能回原件、URL 和抓取账本。追溯、原件和版本是数据验收中的核心约束。

## 四 采集和派生对象语义清晰

block 表示原始结构，chunk 表示后续派生检索单元；两者不可自动互换。S1 的 RAG 禁令适用于其采集阶段；S2 的领域要求完整保留但按选定范围实施。七类组织和内部导入不得无依据并入互联网采集程序。

## 五 保留来源与适用范围

来源国、机构、权威等级、立场和资料版本保持可区分。A—G 知识类别与 A1/A2/B/C 证据等级分开。争议表述、地图视角和文化适用区域依据来源保留，不能自动融合成单一事实或无区域限定的断言。

## 六 接口可校验与失败可解释

数据对象字段、引用和错误状态先明确契约。类型验证和跨文件语义检查分别进行。软件验收使用固定样本和实际运行证据；文档生成成功或样例 schema 通过不等于爬虫功能完成。运行参数和质量阈值不得凭空充当用户承诺。

## 七 范围适度与职责清楚

采用原文支持的采集职责和可分离领域模块。技术选型、物理目录、关系字段、恢复策略和版本规则属于方案候选，需在实施前解决其真实依赖。没有需求依据时不引入 Web 控制台、微服务、向量库或新审批工作流。

## 八 Python 开发约束

用户已明确使用 Python 和 uv；优先 Python 3.9，完整环境无法构建时才按 3.10、3.11 等逐个次版本保守提高。最终实测补丁版本、框架和依赖组合仍待验证确定。遵循根目录 AGENTS.md 的 DEV-001—DEV-012，在 tech-stack.md 完成当前模块需要的选型和验证记录，再初始化依赖该选择的业务模块。文档校验环境的最低 Python 版本不构成业务运行版本决定。

此节属于用户补充指令，不由 S1 的 .py 示例推定，也不表示其他待决业务项已经批准。Agent 可在已有授权内研究、试验和记录工程选型；不得把候选框架当作已确认项目要求。

新增依赖遵循 DEV-007：按实际需求保守增包，优先成熟项目的兼容正式稳定版本，默认排除预发布与浮动 Git 引用；必要升级聚焦相关包并检查锁文件和传递依赖变化。

## 维护与审查

原则变更应记录原因、版本、日期、决策角色以及 spec/plan/tasks/contracts/acceptance 的影响。破坏数据接口时需迁移策略和旧数据可读性说明；原文变动保存新文件指纹和需求差异。勾选开发任务必须有真实实现和验证证据；未选的范围明确记录为不适用。

完整文档入口：[SDD 文档说明](../../SDD文档说明.md)。

## 九 项目目录与运行配置

按用户补充的 DEV-008，源码放 src/，开发结果默认放同级 data/；环境变量提供统一数据根接口，.env 只作显式加载来源。执行 [项目起步说明](../../specs/001-public-knowledge-collection/project-startup.md)，不把工程外生产路径或开发机器配置写死到代码和交付记录。

镜像约束 DEV-009：Python 包必须使用登记镜像，不自动回退官方源；环境模板及来源验收按 [uv 模板说明](../../specs/001-public-knowledge-collection/uv-template.md) 执行。

## 阶段续作与验证收敛

当前已有采集工程实现，按 [阶段续作说明](../../specs/001-public-knowledge-collection/continuation.md) 的 DEV-010—DEV-012 推进有限交付项。适用测试通过后停止测试并交付，业务待决不触发无限夹具完善。用户允许遵守网站规则的有限真实测试；不重复请求同一授权，也不将其扩大为正式采集范围批准。历史测试数只代表对应记录，T012/T019 尚有真实组件/正式验收缺口。

阶段二后续以 [阶段三计划](../../specs/001-public-knowledge-collection/stage-three.md) 的当前状态为准，已完成 NEXT-01/02 不回到 READY。工程预算必须由实际程序执行，结果数上限不等同请求数上限；历史通过证据不得扩大到未验证的安装或正文质量范围。

当前阶段按 [阶段四交付收口](../../specs/001-public-knowledge-collection/stage-four.md) 继续。NEXT-06—NEXT-08 已完成，不作为新一轮默认开发目标；正式业务和组件阻塞继续按证据保留。
