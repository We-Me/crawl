# 公开知识采集与七类知识组织需求规格

## 当前适用入口

已确认业务边界见 [raw 优先决定](raw-first-development.md)，当前实现缺口、任务顺序和完成标准统一见 [阶段五](stage-five.md)。本文历史阶段判断不覆盖该入口；已决定的范围不重复确认，已有能力不重新开发。

版本：0.1.0｜日期：2026-09-11｜状态：评审草案，尚未批准为实施基线

本规格把公开知识采集与七类领域知识组织的四份输入转成可追踪的开发要求。目标是保真、完整、可回溯的数据及明确的后续知识组织边界。当前已有采集程序与有限样本证据；本文保留需求来源，不是本轮执行报告。用户六项范围决定已记录，未选领域仍保留原文追踪。

## 输入与适用规则

S1 为通用采集规范 V1.1，S2 为七类知识来源方案 V1.3，S3/S4 为共同要求和差异审查。版本分别属于各自文件，不互相覆盖。详见 [来源登记](sources.md) 和 [待决事项](clarifications.md)。本项目按 Spec-Driven Development 理解 SDD；参照 GitHub Spec Kit 的规格、计划、任务组织，采用本项目的中文需求和追踪扩展，不宣称符合某项未指定的国家或行业认证标准。

## 范围

采集范围包含公开网页、附件、结构数据发现获取，原件归档，全文与原始结构块，元数据、去重、版本、增量、失败和交付。领域范围包含 A—G 七类知识组织、实体、正式多语对齐、引用和派生切片。两者用语用于本套文档分辨适用条件，不是原文既定的分期裁决。Q01 未决期间，领域需求完整保留，采集与领域的生产实施边界不得自行合并。

S1 明确排除 RAG chunk、token/语义切片、Embedding、向量库、BM25/混合索引、重排、Prompt 证据组织、答案生成和按上下文裁剪。S2 确有这些领域方向及部分最低约束；只有选择相应范围并补齐契约后，才能纳入实施和验收。内部材料走独立受控导入；具体纳入范围见 Q16。站点清单及专属要求在附件登记，尚未现场验证或默认全部启用。

## 用户场景与独立验证

场景优先级是本次实施规划建议，与 S2 七类建设 P0/P1 分开。

| 场景 | 优先级 | 用户价值 | 可独立验证的最小场景 |
| --- | --- | --- | --- |
| US1 采集负责人获取可追溯材料 | P1 | 从公开来源得到原件、全文与抓取依据 | 单个固定 HTML 加附件样本经发现、下载、解析、标准化，形成可追溯文件 |
| US2 数据工程师恢复文档结构 | P1 | 后续无需重新抓取恢复标题、条款和表格 | 直接输入固定原件及账本夹具，验证不同格式结构与清洗，不依赖实时站点 |
| US3 运维人员增量更新和补抓 | P1 | 更新不覆盖历史，失败可以定位恢复 | 给定已有版本库和错误响应夹具，验证重复、修订、下线、补抓与计数 |
| US4 验收人员检查交付 | P1 | 可证明交付范围、内容质量和来源 | 给定一套有效和一套故意损坏的文件，独立检查 schema、引用、禁令和验收证据 |
| US5 领域人员组织协议政策法律术语 | 条件 P2 | A/B/C/G 有正式依据、多语关系及版本 | 给定固定文档夹具，验证双语协定、双方表述、旧法规及缺失语言术语 |
| US6 领域人员组织事件文化地理 | 条件 P2 | D/E/F 保留证据、区域与来源视角 | 给定事件及地图文化夹具验证关联，不以实时抓取为前置；内部导入单独测权限 |

验收场景采用 Given 输入、When 操作、Then 观察结果的形式，逐需求详见 [验收规范](acceptance.md)。

## 需求目录

“共同要求”表示两原文有同一目标，不代表字段层级和具体做法相同；“建议”保留原文强度。FR 为采集功能，NFR 为质量与运行约束，KR 为领域与来源专属要求。所有需求当前状态均为“已提取，待范围基线确认”。

## 采集功能

### FR-001 公开访问与域名边界

仅采集公开可获取内容；遵守来源访问规则；不绕过登录、验证码和访问控制；递归访问限于 allowed_domains。

适用：采集及领域。要求强度：共同要求。来源：S1 §3.4；S2 §1；S3 C02。关联：US1 / T004。待决：Q13。

### FR-002 来源配置与适配器

采用可维护的来源配置驱动不同采集方式；保留来源标识和维护信息；注册表字段映射按候选设计评审。

适用：采集及领域。要求强度：共同目标，结构分别来自两原文。来源：S1 §14；S2 §11；S3 C13/C14。关联：US1 / T004。待决：Q10 Q13。

### FR-003 页面发现策略

固定栏目及结构化入口优先，站内关键词补漏；S1 的列表、搜索、sitemap/API、附件、浏览器兜底顺序与 S2 的 P1—P5 分别保留。

适用：采集及领域。要求强度：共同目标，顺序存在差别。来源：S1 §3.1；S2 §17；S3 C03。关联：US1 / T005。待决：Q12。

### FR-004 宽泛关键词与候选标签

宽泛主题词主召回，正式名称、年份和地点用于补漏；关键词命中不直接决定最终知识分类；category_hint 只表示候选。

适用：采集及领域。要求强度：共同要求。来源：S1 §3.2/§6；S2 §13—14；S3 C04/C05。关联：US1 / T005。待决：Q02。

### FR-005 详情页与正文完整获取

获取最终 URL、标题、来源可提供的发布日期、机构、栏目、正文和附件链接；还原分页、展开和接口加载的正文。

适用：采集。要求强度：S1 明确。来源：S1 §3.3/§9；S4 二 §3.3。关联：US1 / T006。待决：Q06。

### FR-006 附件独立下载与关系

逐个下载附件，记录 attachment_id、文件名、类型、URL、路径和哈希；正文与附件重复时仍保留原始资源身份及关系。

适用：采集。要求强度：S1 明确。来源：S1 §3.3/§6；S4 一 §1.2 附件。关联：US1 / T006。待决：Q05 Q07。

### FR-007 原始资源保真归档

成功取得的 HTML、PDF、DOC/DOCX、XLS/XLSX/CSV、JSON/XML、图片保留原格式字节；不以纯文本替代原件。

适用：采集。要求强度：S1 明确，共同有追溯目标。来源：S1 §4/§13；S2 §18；S3 C07。关联：US1 / T007。待决：Q05。

### FR-008 抓取账本

每个成功取得的资源或 API 响应都有 manifest，记录抓取身份、来源、请求与最终 URL、时间、状态、MIME、原件路径、原件哈希及发现方式。

适用：采集。要求强度：S1 明确。来源：S1 §5；S4 二 五。关联：US1 / T007。待决：Q03 Q15。

### FR-009 完整文档数据

一行一份逻辑文档，保留完整清洗正文及文档表中的必填字段；建议、可选和按需字段不被无依据提升为通用必填。

适用：采集。要求强度：S1 明确。来源：S1 §6；S3 C06。关联：US1 / T009。待决：Q03 Q04 Q06 Q08 Q09。

### FR-010 原始结构块

保留标题、段落、列表、表格、页块等原始单元及顺序；块属于文档，不能基于语义或 token 重组。

适用：采集。要求强度：S1 明确。来源：S1 §7/§9；S3 C08。关联：US2 / T010。待决：Q09。

### FR-011 PDF 与 OCR 定位

文本 PDF 保留页码、段落及表格；扫描 PDF/图片保留 OCR 文本并标注 extraction_method；按源要求保留置信度及页码映射。

适用：采集。要求强度：S1 明确，页码字段等级保留差异。来源：S1 §7—9/§13；S2 §18；S3 C08。关联：US2 / T011。待决：Q04 Q11。

### FR-012 Office 与结构数据解析

DOC/DOCX 保留标题样式、段落、表格、列表；XLS/XLSX/CSV 保留 sheet、表头、行号、单元格及单位；JSON/XML/API 保留字段结构、分页和请求参数。

适用：采集。要求强度：S1 明确，S2 有结构保留目标。来源：S1 §8/§10；S2 §11 Table/Data Loader；S3 C09。关联：US2 / T012。待决：Q08。

### FR-013 保真清洗与标准化

去除非正文导航、广告和推荐，保留正文顺序、标题、列表及条款；规范日期和 URL；保留无法确定的 raw_date；识别语言但不翻译、改写或摘要。

适用：采集。要求强度：S1 明确。来源：S1 §9；S4 二 九。关联：US2 / T013。待决：Q06。

### FR-014 去重与来源关系

支持 URL、原件哈希与近似正文重复识别；保留转载、镜像和正文附件关系；不得因相似度丢失不同立场或真实修订。

适用：采集及领域。要求强度：共同要求，物理策略待定。来源：S1 §3.3/§11；S2 §11；S3 C10。关联：US3 / T014。待决：Q04 Q05 Q11。

### FR-015 历史版本与失效记录

内容变化保留新旧版本；历史旧版不得覆盖现行版；页面下线保留历史并记录 source_status；法律有效性不得仅由抓取新旧推断。

适用：采集及领域。要求强度：共同要求。来源：S1 §11/§13；S2 §6/§18；S3 C11。关联：US3 / T014。待决：Q04 Q09。

### FR-016 分类增量更新

新闻按发布增量，法规检查状态和哈希，统计按版本/年份；支持不同类别更新；保留 ETag/Last-Modified（来源可用时）。

适用：采集及领域。要求强度：共同目标，周期为建议。来源：S1 §11；S2 §12；S3 C12。关联：US3 / T015。待决：Q13 Q15。

### FR-017 失败记录与补抓

抓取、下载、解析、标准化失败记录来源、URL、时间、阶段、错误类型、信息、重试次数和后续动作，支持复现及补抓。

适用：采集。要求强度：S1 明确。来源：S1 §12/§13；S3 C15。关联：US3 / T016。待决：Q15。

### FR-018 运行日志与交付对账

交付 logs/，记录运行、数量、重复、异常；成功、失败、跳过与处理状态按不同计数口径对账。

适用：采集。要求强度：S1 正文明列强制。来源：S1 §2/§12—14；S4 一 §1.3 logs。关联：US3 / T017。待决：Q11 Q15。

### FR-019 采集成果文件交付

采集范围采用 S1 时交付 raw/、crawl_manifest.jsonl、documents.jsonl、blocks.jsonl、failed_records.jsonl、logs/；目录示例与代码目录分别标识。

适用：采集。要求强度：S1 明确。来源：S1 §2/§4.2/§15；S4 二 最终交付物。关联：US4 / T018。待决：Q01 Q14。

### FR-020 采集阶段边界

S1 采集实施范围不生成 chunks.jsonl，不做 token/语义切片、向量化、向量库、BM25/混合索引、重排、Prompt 证据组织或答案生成，不按上下文裁剪。

适用：采集，与领域阶段有冲突。要求强度：S1 明确禁止。来源：S1 §1.2/§7.1/§15；S2 §1/§4/§16/§18；S4 一 §1.1。关联：US4 / T018。待决：Q01。

## 质量与运行

### NFR-001 端到端可追溯

按 S1 原口径，documents/blocks 100% 可回到 source_url、raw_path 和 crawl_manifest；跨文件关联实现为待决设计。

适用：采集及领域。要求强度：S1 建议验收口径含 100%。来源：S1 §13；S2 §18；S3 C01/C16。关联：US4 / T019。待决：Q03。

### NFR-002 JSONL 与字段约束

UTF-8，每行一个合法 JSON 对象，必填字段通过与已选范围对应的 schema；必须保留原文必填层级区别。

适用：采集。要求强度：S1 明确验收内容。来源：S1 §13；S4 二 十三。关联：US4 / T019。待决：Q06 Q08 Q09。

### NFR-003 请求控制参数

保留单域通常 1—3 req/s、连接约 10 秒、读取约 30 秒、指数退避重试 2—3 次的原文建议；按站点调整，永久性 4xx 不盲重试。

适用：采集。要求强度：S1 建议参数。来源：S1 §3.4；S4 一 §1.3 运行参数。关联：US1 / T006。待决：Q13。

### NFR-004 内容与结构质量

检查正文、标题、列表、表格、页码及条款完整性；总体召回率、抽样比例、OCR 准确率和近似去重阈值由项目评审定义。

适用：采集及领域。要求强度：两原文均要求质量检查，通用阈值缺失。来源：S1 §13；S2 §18；S3 C16。关联：US4 / T019。待决：Q11。

## 领域与来源

### KR-001 来源等级与立场

保存来源国家/机构、权威性和立场，区分 A1/A2/B/C 证据等级与 A—G 知识类别；双方有争议的陈述分别保留。

适用：领域，采集扩展待定。要求强度：S2 明确。来源：S2 §1—3/§5/§18；S4 一 §1.2。关联：US5 / T020。待决：Q01 Q10。

### KR-002 协定与机制组织

A 类保留正式协议、多语版本、签署/生效日期、正式语言、条款号和引用锚点；按 agreement_id 对齐；原文提出按章条款项切片。

适用：领域。要求强度：S2 明确与建议并存。来源：S2 §4/§16 A。关联：US5 / T021。待决：Q01 Q02 Q04 Q09。

### KR-003 政策立场与表述组织

B 类保留 stance、speaker、organization、event_date、publication_date、issue_tags、related_agreement_ids；发布机构、时间和立场必须可查。

适用：领域。要求强度：S2 明确。来源：S2 §5/§16 B/§18。关联：US5 / T021。待决：Q01 Q02 Q10。

### KR-004 法律法规组织

C 类保存公布、施行、有效性、修改/废止、条款及司法辖区；按章条/Section 组织，版本、时效、废止关系强制保存。

适用：领域。要求强度：S2 明确。来源：S2 §6/§16 C/§18。关联：US5 / T021。待决：Q01 Q02 Q04。

### KR-005 事件与证据关联

D 类建立 event_id，分别关联中方、印方、共同声明、依据协定、地点、参与者、后续事件；不只是堆放新闻全文。

适用：领域。要求强度：S2 明确，实体字段为建议。来源：S2 §7/§16 D。关联：US6 / T022。待决：Q01 Q02 Q09。

### KR-006 内部材料受控导入

内部案例、纪要、转写不进入公共爬虫；若纳入项目，离线导入需分类分级、脱敏、权限标签和审计。

适用：领域，内部导入单独待定。要求强度：S2 明确流程边界。来源：S2 §1/§7/§11 Controlled Import；S4 一 §1.1。关联：US6 / T022。待决：Q01 Q16。

### KR-007 文化知识区域化

E 类按地区、社区、主题组织；保留 source_region、source_authority 和适用范围；统计信息优先官方表；不将地方习俗泛化为整个国家。

适用：领域。要求强度：S2 明确，组织键为建议。来源：S2 §8/§16 E。关联：US6 / T023。待决：Q01 Q02 Q09。

### KR-008 地名地图与来源视角

F 类保留名称、别名、行政层级、地图版本、来源国家和视角及有效期；中印资料分别保留，争议边界不自动几何融合。

适用：领域。要求强度：S2 明确，实体字段为建议。来源：S2 §9/§16 F；§15 IN-10。关联：US6 / T023。待决：Q01 Q02 Q09 Q10。

### KR-009 多语术语实体

G 类以 concept_id 关联 zh/en/hi 正式写法、别名、旧称、推荐译法和来源；依据正式多语材料，保留 jurisdiction 和有效期；不以开放词典覆盖官方译名。

适用：领域。要求强度：S2 明确，字段表为建议。来源：S2 §10/§16 G。关联：US5 / T024。待决：Q01 Q02 Q09。

### KR-010 领域切片与检索交接

S2 提出结构化、全文、向量、图谱和混合检索组合；chunk 必须带 source_url、citation_anchor、content_hash、crawl_time，PDF 还须页码；模型、索引和部署参数未给定。

适用：领域，与采集范围冲突。要求强度：S2 描述目标及最低字段。来源：S2 §1/§3/§16/§18；S4 一 §1.1。关联：US5 / T025。待决：Q01 Q02 Q04 Q17。

### KR-011 关键词验证与歧义控制

每来源至少验证 10 个种子关键词并记录无结果/误召回；区分印度与印度尼西亚，LAC 结合 China/India-China 等上下文；主词通常 8—15 个为建议。

适用：领域来源验收。要求强度：S2 最小验收要求。来源：S2 §13/§18；S4 一 §1.3。关联：US4 / T026。待决：Q11 Q12 Q13。

### KR-012 七类更新与建设顺序

保留 A 每周及重大文件触发、B 每日、C 每周及新法触发、D 每日并历史回填、E 月/季、F 季及区划变更、G 随 A/B/C/F 同步的建议；A/B/C/G 为原文 P0。

适用：领域。要求强度：S2 建议。来源：S2 §12；S4 三 §12。关联：US5 / T015。待决：Q01 Q13。

### KR-013 来源专属规则保留

保留来源专属入口、过滤条件、主键、采集边界和字段要求；S4 曾暂不整理站点细节，不代表 S2 的原文要求消失。
