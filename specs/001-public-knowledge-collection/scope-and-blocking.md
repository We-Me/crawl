### 组件缺失时的安装预案（用户已完成安装，当前不重复执行）

首选由管理员在已有 Ubuntu 24.04 目标环境安装发行版维护的稳定组件。先核查当前配置的系统镜像与候选版本，不照抄历史版本号、不启用 backports 追新；PyPI 镜像与 apt 系统镜像分别管理。

```bash
# 管理员在目标 Ubuntu 主机执行；sudo 密码由管理员在终端输入
sudo apt-get update
apt-cache policy libreoffice-writer libreoffice-calc
sudo apt-get install --no-install-recommends libreoffice-writer libreoffice-calc

# 以实际运行爬虫的用户执行
command -v soffice libreoffice
soffice --version
# 在项目根目录，复用现有 uv 环境检查程序能否发现组件
uv run --locked --no-python-downloads python -c "from crawler.parser.legacy_parser import find_soffice; p=find_soffice(); print(p); assert p, 'LibreOffice not found in runtime PATH'"
```

若组件装在非标准目录，由管理员将包含 soffice 的目录加入实际运行用户的 PATH（服务部署时设置对应服务环境），随后执行上面的发现检查。当前代码只通过 PATH 查找 soffice/libreoffice，没有专用的 LibreOffice 路径环境变量，不虚构 .env 配置项。

若无法取得安装权限，可由管理员提供预装组件的目标 Linux 运行环境，或提供能满足 parse_legacy(converter=...) 接口的转换器。现有注入是 Python 函数接口，接收原始 bytes 与扩展名，返回转换后 bytes 与 .docx/.xlsx 扩展名；它不是现成 CLI 配置开关。采用替代转换器前需记录选型与接线变更并针对验证，不默认新增依赖或重构部署体系。
