# 两份需求文件的共同要求

本文只整理 V1.1 与 V1.3 都有明确依据的共同目标或要求。“共同”不表示两份文件的字段、必填等级、阶段范围和交付方式已经一致；这些差异另存于《需求审查_差异与单方要求.md》。暂不涉及具体站点的爬取规则。

## 审查依据

- **V1.1**：[一般爬虫采集与标准化数据交付需求规范_V1.1_仅采集整理.docx](一般爬虫采集与标准化数据交付需求规范_V1.1_仅采集整理.docx)。
- **V1.3**：[七类知识库知识来源与采集方案_V1.3_宽泛检索关键词版.docx](七类知识库知识来源与采集方案_V1.3_宽泛检索关键词版.docx)。

两份文件的版本号分别属于各自文件；原文未声明 V1.1 覆盖 V1.3，或 V1.3 覆盖 V1.1。下文通过“版本 + 原章节”定位依据，不推定优先级。

## 二 共同要求不构成的实施结论

以上对照不能推出以下设计已经得到两份文件共同确认：

- V1.1 或 V1.3 自动覆盖另一份文件。
- block 与 RAG chunk 是同一对象。
- 七类知识必须分目录存储，或必须共享正文并通过引用清单组织。
- 同一份文档必须支持何种多分类、人工审核或发布状态流程。
- document、block、chunk、事件、术语、地理实体之间已经有完整字段映射。
- 开发与交付必须采用此前提出的 workspace/、deliveries/ 和批次目录布局。

具体字段、原文目录、七类组织要求、单方提出的约束和未明确事项见[差异与单方要求](需求审查_差异与单方要求.md)。
