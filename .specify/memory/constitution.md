# 公开知识采集项目开发原则

## 当前执行与完成口径（2026-09-14 用户补充）

当前以 [阶段七](../../specs/001-public-knowledge-collection/stage-seven.md) 为唯一任务入口；早期阶段追加记录已单独归档。用户明确不以覆盖所有异常、修复全部缺陷作为基础成品条件。关键原件/追溯/状态真实性缺陷须修复或可靠隔离；可控异常允许通过错误账、有限重试和人工处置管理后交付。基础软件完成与某批数据完整验收分开记录，不将有账失败伪装成功，也不因非阻断错误无限延长开发。详细退出条件只在阶段七维护；本次仅更新开发与验收范围解释，未修改四份输入或冻结数据格式。

版本：0.1.0｜日期：2026-09-11｜状态：评审草案，尚未批准为实施基线

本文件规定本项目的规格维护与实施约束。业务事实来自四份保留输入；新增工程处理明确标注为设计建议。原则版本为 0.1.0，编制日期为 2026-09-11，批准人及批准日期尚未确定。它是可评审候选，不代表项目已完成业务决策。

## 一 需求先于实现

每项业务实现对应稳定需求编号、可观察验收结果和输入依据。先维护 spec.md，再同步 plan.md、数据契约、tasks.md 与追踪矩阵；不能以代码现状反向伪造原文要求。计划变化需记录受影响需求和测试。

## 二 保留依据和强度

S1/S2 不因版本数字互相覆盖；S3/S4 是审查依据，不自动替代原件。原文的必须、建议、可选、条件必填、按需，以及两原文的阶段差异都必须保留。设计补充需要自己的决策记录；无法确定的事项可留待决而不能假定已批准。

## 三 原件保真与可追溯

公开采集结果保留原始资源、抓取依据和完整正文结构。采集清洗不翻译、摘要或改写事实。新版本不覆盖历史；失败不被静默丢弃。采集输出要能回原件、URL 和抓取账本。追溯、原件和版本是数据验收中的核心约束。

## 四 采集和派生对象语义清晰

block 表示原始结构，chunk 表示后续派生检索单元；两者不可自动互换。S1 的 RAG 禁令适用于其采集阶段；S2 的领域要求完整保留但按选定范围实施。七类组织和内部导入不得无依据并入互联网采集程序。

## 五 保留来源与适用范围

来源国、机构、权威等级、立场和资料版本保持可区分。A—G 知识类别与 A1/A2/B/C 证据等级分开。争议表述、地图视角和文化适用区域依据来源保留，不能自动融合成单一事实或无区域限定的断言。

## 六 接口可校验与失败可解释

数据对象字段、引用和错误状态先明确契约。类型验证和跨文件语义检查分别进行。软件验收使用固定样本和实际运行证据；文档生成成功或样例 schema 通过不等于爬虫功能完成。运行参数和质量阈值不得凭空充当用户承诺。

## 七 范围适度与职责清楚

采用原文支持的采集职责和可分离领域模块。技术选型、物理目录、关系字段、恢复策略和版本规则属于方案候选，需在实施前解决其真实依赖。没有需求依据时不引入 Web 控制台、微服务、向量库或新审批工作流。

## 八 Python 开发约束

用户已明确使用 Python 和 uv；优先 Python 3.9，完整环境无法构建时才按 3.10、3.11 等逐个次版本保守提高。当前 CPython 3.9.25 与采集依赖组合已验证并锁定，续作复用 tech-stack.md 记录。遵循根目录 AGENTS.md 的 DEV-001—DEV-013，在 tech-stack.md 完成当前模块需要的选型和验证记录，再初始化依赖该选择的业务模块。文档校验环境的最低 Python 版本不构成业务运行版本决定。

此节属于用户补充指令，不由 S1 的 .py 示例推定，也不表示其他待决业务项已经批准。Agent 可在已有授权内研究、试验和记录工程选型；不得把候选框架当作已确认项目要求。

新增依赖遵循 DEV-007：按实际需求保守增包，优先成熟项目的兼容正式稳定版本，默认排除预发布与浮动 Git 引用；必要升级聚焦相关包并检查锁文件和传递依赖变化。
